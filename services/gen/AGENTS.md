## シード

```
if frozen_seed.is_some() { seed = frozen_seed }   // 再計算しない
else { seed = SHA256(algo_version || atelier_id || date || concat(sorted(schiil_sha256))) }
```

再生成時にシードを再計算すると BSP の分割そのものが変わり、構図が丸ごと入れ替わる。
除去したタイルだけを VoidCell 化するために、シードは初回生成時に確定させ以後不変とする。

PRNG は `rand_chacha` の ChaCha20。`ThreadRng` や MT19937 を使わない。
言語をまたいで同じ順列を再現する必要がある。

**`generation_seed` と `lottery_seed` は別物。** 前者は入力ハッシュ由来で構図を決める。
後者はサーバー CSPRNG 由来で抽選を決める。抽選に `generation_seed` を流用しない
（画像を作り直して当選を狙う余地が生まれる）。

## 分割（BSP）

- 面積上位45%からランダムに1つ選び、長辺方向に分割する
- 分割位置 = `len/2 + (rng()*2-1) * variance * len * 0.34` を整数に丸める（variance 既定 0.55）
- 整数格子上で行う。サブピクセルを作らない
- **面積は不揃いになる。これは意図した仕様。均等化しない**
- 未投稿スロットの矩形も VoidCell として確保する

## 描画

- 入力は常に 1080x1080
- タイルの縦横比に合わせてセンタークロップ（正方形固定ではない）
- area-average 縮小 -> Oklab 変換 -> 32色パレットへ最近傍量子化 -> Floyd-Steinberg 誤差拡散
- 領域境界に輪郭線を引かない
- **絵として成立させる必要はない。** 構図の美しさや統一感を作り込もうとしない
- ただしピクセルアートである必要はある。写真の粗いモザイクに見えてはいけない

## 必ず書くテスト

1. 同じ入力で2回実行し、出力PNGのバイト列が完全一致する
2. `--frozen-seed` 指定で入力から1枚除いた再実行が、除いたタイル以外バイト単位で一致する
3. 参加人数 1/3/7/12/50/200/500/2000 で分割が破綻しない
4. 1アトリエ200ms以内

浮動小数点の演算順序を固定すること。並列化しても結果が変わってはいけない。

## WASM

分割ロジック（BSPのみ）を WASM として書き出す。API とモバイルはこれを使う。
**TypeScript で再実装しない。** ずれると「今日のキャンバス」と生成物が食い違う。
Rust 側と TypeScript 側で同じ矩形リストが返ることを比較テストで検証する。
