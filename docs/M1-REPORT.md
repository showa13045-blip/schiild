## 性能の境界

最適化後のローカル生成コア測定: 2000人・約128〜143ms（PNG出力まで、画像前処理を除く）。
これをM1全処理200msの達成と扱わない。CLI比較バッチはJPEG処理を含み、人数が多いケースで秒単位になる。性能要件の短縮や適用範囲変更は未承認。

入力読み込みの重複排除・前処理の並列化を追加実施した。今後の性能対応候補は、画像受け取り時のOklab平均の事前計算。M2で実装済みとは扱わず、本PRの未達項目として残す。

## 仕様変更・留意点

バケット部分再生成の前版入力方式はユーザー承認済み。BSPも初回メタデータ保持のためCLI再生成には前版state.jsonを必要とする。
入力形式、乱数の整数化、補間・署名・指標計算の具体化はservices/gen/README.mdに明示した。特に補間の距離・重み、指標の算式は仕様に数値定義がないため暫定の実装規約としてレビュー対象。
元のrequirements.md / copy.md / legal.mdは変更していない。共有tokens.ts / copy.tsも変更していない。
暫定パレットと合成入力での比較は、実写真でのピクセルアートらしさの合格判定にはならない。ガターの決定と本番パレットは人間のレビュー待ち。

`M1-PERFORMANCE.md` と `m1-evaluation/optimization-timings.json` に追加測定を記録した。8画像再利用の2000人ケースは約113〜120msへ短縮したが、2000枚の異なるJPEGでは約7.66秒であり、全処理200ms条件は未達のまま。

## 承認された前処理分離の実装

2026-09-08、ユーザーの「続けて」を受け、バケット方式のJPEG検証・Oklab平均計算を投稿時の前処理として分離した。`--prepare-image`（1枚）、`--prepare-bucket`（評価用一括）、`--prepared-bucket`（日次生成）を追加。
異なるJPEG2000枚の平均色を使う日次CLIは5回で約101〜121ms。入力ファイル読み込み・PNG出力・保存まで含み、前処理は含まない。従来の6成果物とのバイト一致を確認。これにより、承認された「バケット日次処理200ms」のローカル条件を満たした。従来の全処理200msやBSP全処理の達成とは扱わない。
CLI契約と信頼境界はservices/gen/README.md、測定はM1-PERFORMANCE.mdに記録。M2/M3は未着手。PRは人間のパレット・ガターレビュー等を残すドラフト。
