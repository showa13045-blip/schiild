# 公式アトリエのQR写真受付

既存のLINE・Apple・WhatsApp認証後に写真を送る、公式アトリエ向けの受付導線です。認証・参加・一日一枚・画像審査・生成の既存処理を再利用し、GLOBALへの記録は追加しません。課金、APIキーによる第三者サーバー連携、ファンクラブ会員照合はこの変更に含めません。

## 使い方

1. 公式アトリエの作成者としてログインし、そのアトリエの今日の画面にある「QR写真受付」を開きます。運営者は `/atelier-reception/?code=招待コード` からも管理できます。
2. 「写真を受け付ける」をオンにし、送信後の行き先を選んで保存します。初期状態は受付停止です。
3. 表示されたQRコードを保存し、会場やサイトへ設置します。画像は余白付き1024px指定のSVGで、拡大印刷できます。QR生成に外部サービスは使いません。
4. ファンクラブサイトを経由する場合は、ログイン情報を含まない公開HTTPSのURLを設定します。サイト側へ「サイトへの埋め込み」のscriptタグを設置すると、写真受付とSchiildで作品を見る二つのリンクが表示されます。外部サイトへSchiildの認証情報は渡しません。

受付URLからは、ログイン・明示的なアトリエ参加・カメラ撮影・投稿ルールと画像審査への同意・最終確認の順に進みます。写真は1080×1080のJPEGです。撮影のみで、アルバム・フィルタはありません。認証終了後は有効期限20分の同一サイト内の戻り先へ復帰します。

送信後は、設定したサイト、SchiildのWeb版の対象アトリエ、App Storeへのリンクを表示します。ファンクラブサイトへのリンクには `schiild_return` としてSchiildの閲覧用URLが付きます。ファンクラブサイト自体を変更するには、サイト管理者による埋め込み設置が必要です。実際のサイトURLは未設定であり、架空のURLを公開環境には保存していません。

Schiildの作品へのリンクは現在Web版を開きます。既存iOSバイナリに新たなUniversal Linksは追加していません。App Storeへのリンクはアプリの入手・起動用で、対象アトリエをネイティブ画面へ直接渡す機能とは異なります。

## 権限と制約

- 公認設定を持つ公式アトリエだけが対象です。作成者・既存の運営者だけが設定を変更できます。認証マークを利用者自身が付ける権限は追加しません。
- 写真送信は有効なログインと現在の所属をAPIで確認します。QRを知っているだけでは投稿できません。参加は既存の参加処理と人数制限を通します。
- 受付キーは128ビットの乱数です。公開メタデータはアトリエ名・コンセプト・受付情報だけで、プロフィール・元写真・認証情報は含みません。キーの再発行は旧URLを失効させます（API対応、管理画面には再発行ボタンを追加していません）。
- UTCの当日だけ投稿できます。日付が変わったら古い画面からの送信を拒否します。画面には端末の時間帯付きで対象時間の窓を表示します。
- 既存の投稿APIへ再度ディスパッチするため、同意・元画像の正規化・投稿回数・画像審査・通知・生成・審査落ちの当日再投稿を迂回しません。既に受け付けた同じ送信の再試行は既存APIの冪等処理となり、写真や通知を増やしません。
- 受付停止中は新しい参加・投稿を止め、作品を見る導線は残します。退会・アカウント削除後の投稿はできません。
- サイトURLは公開用HTTPSに制限し、ユーザー名・パスワード・非標準ポート・Schiild自身への循環する行き先を拒否します。任意URLのサーバー側取得は行いません。
- 隔離された審査モードには受付機能を公開しません。一週間の架空利用例にも管理リンクを追加しません。

## 追加されたファイル

`apps/ios/server/atelier-reception.mjs` が権限・SQL設定・受付の委譲を担当し、`reception-copy.mjs` / `reception-pages.mjs` / `reception-surface.mjs` が10言語の画面と埋め込みを担当します。`apps/demo/server/reception-qr.mjs` はMITライセンスのqrcode 1.5.4によるSVG生成です。

`patch-reception-runtime.mjs` は公開中Workerの認証済みactor境界と公開アクション一覧を厳密に照合し、差分だけを追加します。古いローカルのWorker全体で公開環境を上書きしないためのものです。

新テーブル `atelier_receptions` は既存SQLiteに追加されます。既存アカウント・アトリエ・画像・審査・チャットの表やレコードを初期化しません。公開時は現行モジュールをバックアップし、現行の認証・SSO・通知・静的アセット・シークレットを保持します。直前の公開内容と設定が変わっていた場合は反映を中止します。
