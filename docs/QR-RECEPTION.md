# 公式アトリエのQRと写真受付

2026-11-18更新: QRは、各団体の公式アトリエを通常のアプリで開く入口になりました。写真専用画面から始まる以前の動線は既存のQRも含めて変更しています。詳細・iOS更新状況は `apps/ios/UNIVERSAL-LINKS.md` を参照してください。

## QRの使い方

公式アトリエの作成者としてログインし、今日の画面の「アトリエのQRコード」を開きます。写真受付のオン・オフに関係なく、QR・団体固有のURL・サイト用リンクを取得できます。Picklemate以外にも同じ実装を使い、招待コードに応じて移動先を分けます。

URLは `https://schiild.app/atelier/招待コード/`、SVGはその末尾の `qr.svg` です。対応iOS版ならインストール済みアプリを開き、その他はWebへ進みます。所属済みなら対象アトリエの通常画面、未所属なら既存のログイン・参加の画面を使います。以後は通常のタブを操作できます。新しいiOS版は無料ビルド枠の回復待ちで、現在はWebの直接遷移を利用できます。

## 既存の写真受付

以前のQRキーに対応するカメラ受付は `/collect/受付キー/photo/` に移しました。既存のLINE・Apple・WhatsApp認証、明示的参加、1080×1080撮影、投稿ルール・自動審査への同意、確定を経て、従来の投稿パイプラインへ委譲します。GLOBALへ勝手に記録しません。

作成者と既存の運営者だけが、受付の有効化、送信後のSchiild直接表示/ファンクラブサイト経由、公開HTTPSの行き先を設定できます。版番号で競合を拒否します。元の受付キーを持つだけでは投稿できず、現在の所属とログインが必要です。UTCの日付が変わった写真の投稿は拒否します。画像の正規化・投稿回数・自動審査・再送の冪等性・当日だけの審査落ち再撮影は既存処理を通します。

ファンクラブサイトへの行き先には閲覧用URLを `schiild_return` として付け、サイト側でSchiildへ戻すリンクを置けます。Schiildの認証情報は渡しません。任意URLのサーバー側取得は行いません。元の `/collect/受付キー/` と `/view/` は、写真撮影ではなく同じ団体のアトリエへ転送します。旧キーを再発行して失効させた場合は転送できません。

追加テーブル `atelier_receptions` は公式アトリエごとの設定を保持し、既存アカウント・画像・作品を初期化しません。隔離されたApp Reviewと架空の一週間の利用例へ通常データを持ち込みません。QR画像はqrcode 1.5.4（MIT）でローカル生成し、外部QRサービスへ情報を送りません。

課金、パートナー用APIキー、第三者サイトの有料会員照合は今回のリンク機能に含みません。サイトへのリンク設置は、そのサイト管理者が行います。
