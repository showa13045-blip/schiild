## トークン

```
面    bg #F6F5F3 / surface #FFFFFF / sunken #EDEBE8 / fill #14130F
文字  ink #14130F / ink-2 #55524B / ink-3 #8C887F
線    line #E2DFD9 / line-strong #C9C5BD
赤    danger #A32D2D / danger-line #E8CFCF
```

- **アクセント色を持たない。** 有彩色は `danger` のみ。破壊的操作とエラー以外に使わない
- 赤は3段階: 文字色（設定の削除行）< 輪郭線（預かりの辞退）< 塗り（アカウント削除）
- 角丸: 控え 8 / カード 12 / **作品コンテナは必ず 0**（四隅のピクセルが欠けるため）
- 余白: 4/8/12/16/24/32/48 のみ。スケール外の値を使わない
- 書体: `Inter, 'Noto Sans JP', sans-serif`（**この順序を守る**。逆順だと全て Noto になる）
  Noto Sans JP は 400/500 のみ読み込む。**明朝体を使わない**
- 作品番号・日付・人数・座標は必ず等幅。`letter-spacing: .1em` の小さな等幅ラベルが識別性を担う
- **ライトモード専用。** `color-scheme: light` を明示する

生の HEX をコンポーネントに書かない。型付きの定数を経由する。
装飾がないため崩れをごまかす手段がない。余白とタイポの精度への要求が通常より高い。

## 状態画面を後回しにしない

S-08 空状態 / S-09 投稿済み / S-10 生成失敗 / S-11 除外通知 / S-17 削除。
フロント工数の3〜4割を占める。

- 空状態で謝罪しない。「まだ〜がありません」ではなく行動から始める
- 使えない機能はグレーアウトせず、存在させない（無効化は「押せるはず」を想起させる）
- 失敗時に仮画像やスピナーを置かない。何が起きたかと、記録が無事であることを先に書く
- 行き止まりを作らない。最後の一文で次に接続する

## 開封演出（§6.5）

三拍構成。タイル230ms間隔でランダム順 -> 500ms後に記録 -> さらに1000ms後に預かり手。

- **タイルの出現にトランジションを付けない。** フェードすると画面効果になり、置かれる手触りが失われる
- **作品と抽選結果を同時に出さない。** 同時だと視線が結果へ行き、作品を見なくなる
- 未描画セルも同じ順序・同じ重みで置く
- 初回のみ再生。二度目以降は即座に完成形
- 再生中のタップでスキップできること。`prefers-reduced-motion` では演出しない

## 確認ダイアログ（§6.6）

代替不能な操作（投稿の確定、預かりの辞退、アカウント削除）だけモーダルにする。
代替可能な操作（アトリエの定員）はモーダルを出さず、注意書きと結果のプレビューで助ける。
**全ての不可逆操作をモーダルにしない。** 全部を重くすると本当の場面の重みが薄れる。

## カメラ

入力はアプリ内カメラのみ。**アルバム導線を実装しない。**
撮影後、クライアント側で 1080x1080 / JPEG q85 へ正規化してからアップロードする。
権限拒否の状態を必ず実装する。唯一の入口であり、無いとその日の記録が不可能になる。
アップロード失敗時は正規化済み画像を端末に保持し、締切まで再送を試みる。
