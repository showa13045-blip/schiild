# 利用者ブロック

2026-10-28。本人が承認したデモ／iOSの表示方針に限る実装。本番M1〜M4には使用しない。

- 作品の「通報・ブロック」で他の利用者のシールを選び、ブロックする。
- 自分のシールは対象外。対象者のアカウント識別情報はクライアントへ返さない。
- 設定の「ブロックした利用者」から解除する。起点となったシールの日付と1始まりの座標で識別する。
- 文言と設定リンクは全10言語に対応し、言語変更にも追従する。

## 表示と保存

`personal_blocks` は、表示する本人と対象者の内部参照を持つ非公開のSQLiteテーブル。
クライアントから指定された利用者IDを信用せず、権限確認済みの作品の選択キーから対象を解決する。
同じ写真を使った別の利用者には適用しない。

アトリエ作品、公開アトリエ、生成前の暫定表示、アーカイブで取得する画像を、本人への応答でだけマスクする。
GLOBALの概要画像と拡大画像にも適用する。共有画像のバイト列、人数、作品サイズ、配置、座標、預かり手は変更しない。
GLOBALには本人の設定に応じたリビジョンを使い、変更前の座標・拡大画像キャッシュを拒否する。
運営者の通報・公開前確認画面は、確認に必要な画像を閲覧できる。

設定はアカウントに保存するため、別のログイン後も維持する。
退会処理と同じトランザクションで本人の一覧を消去する。
対象者の退会時は、共同作品と同じ匿名参照へ置き換え、アカウントとの関連を残さず過去の非表示を維持する。
明示的な新規登録は新しいアカウントなので、以前の対象者との関連を持たない。

## 配信と検証

`scripts/prepare-blocking.mjs` は現行配信コードへ差分だけを追加する。
現在のApple／LINE／WhatsApp認証、シークレット、画像、他の配信モジュールを古いデモ実装で置き換えない。
通常環境と審査環境は異なるDurable Objectを使う。

ローカルの一時SQLite、実際の配信ファイルを使う統合検証、全10言語のブラウザ検証を実施。
公開先の審査専用環境でも、本人だけの非表示、再ログイン後の保持、他人からの解除拒否、解除後の画像復元を確認した。
通常利用者の投稿や設定を検証のために変更していない。

```powershell
node --experimental-strip-types --test apps/ios/tests/personal-blocks.test.mjs
node apps/ios/scripts/check-review-runtime.mjs ../../work/personal-block-stage
```

実機の最終確認は別途必要。審査提出、素材の権利申告、App Privacyの公開は行っていない。
