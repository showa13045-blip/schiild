# Schiild デモ — 友達とつくるシールト

アトリエを作成して友達を招待し、それぞれのカメラで撮った写真から同じシールトを生成できます。公開先は `https://schiild.pickleballnavi.jp/`。Xserverには静的UIと画像だけを置き、Cloudflare WorkersとSQLite Durable Objectで共有API・参加状況・生成・抽選を処理します。スマホではページ全体を縦にスクロールできます。

`demo`ブランチ専用です。本番のM1〜M4、API、DB、Rust/WASMには接続しません。TypeScript生成エンジンと暫定32色は、このデモだけで使います。

## 友達との使い方

1. 「アトリエ ＋」から「アトリエをつくる」を開き、名前と定員を決めます。
2. 表示された招待リンクか8文字のコードを友達へ渡します。
3. 友達が「参加する」を押すと、当日から写真を記録できます。
4. 参加者が「このアトリエに1日1枚」から撮影し、確認画面で写真の送信を確定します。
5. 写真が集まったら、作成者が「シールトを生成する」を押します。現在の投稿数と受付終了の説明を確認すると、作品が生成されます。
6. 参加者は「ひらく」から同じ作品を開封できます。その作品はアーカイブにも残ります。各日付の「GLOBAL SCHIILD」から、その日の共有GLOBALを開けます。預かり手が他の人でも閲覧できます。
7. アトリエ選択画面の各行にある「アトリエを抜ける」で退会できます。ログインし直しても、抜けたアトリエは参加一覧へ復元されません。招待コードから再参加できます。

退会しても、投稿済みの区画・写真・完成作品・GLOBALのピクセルはそのまま残ります。作成者が抜けると、残っている最初の参加者へ生成権限を引き継ぎます。全員が抜けてもアトリエと記録は削除せず、最初に再参加した人が生成できるようになります。投稿済みの区画を別の参加者が使えるのは翌日からです。未投稿の区画は当日から再利用できます。同じ人が当日戻る場合は、自分の投稿済み区画へ戻れます。端末内アトリエの履歴もブラウザ内に残し、同じコードでの再参加時に復元します。

[ASSUMPTION / ユーザー承認済み] デモの退会・生成権限の引き継ぎ・再参加を追加します。元の投稿を取り消さず、日付ごとに当時の参加者と区画の対応を保存して、過去の作品を描き直さない実装です。退会は再参加できるため、追加の確認モーダルを置かず、一覧に結果を説明します。

生成後は、その日の写真を追加できません。翌日の受付はUTC 00:00（JST 09:00）に始まります。同じブラウザで同じ日に記録した写真は、複数のアトリエでも同じ画像を使います。写真の差し替えはできません。

## 今日のシールトの仮生成（デモ専用）

今日の画面の「今日のシールトを仮生成する」から、その時点で集まっている写真をすぐ画像にできます。共有アトリエでは参加者全員が使え、1枚以上の投稿が必要です。正式生成の前に何度でも試せます。投稿の受付は続き、正式作品・抽選・アーカイブ・GLOBAL・投稿済み区画は変更しません。「デモ専用・仮表示」を明示して表示し、戻る・再読み込み・日付変更・正式生成で仮表示を破棄します。画像はサーバーや端末のストレージへ保存せず、表示中だけメモリに置きます。生成失敗時に仮の代替画像を出しません。

「ひとりで試す」のアトリエにも同じボタンがあります。ここでは既存のサンプル参加者を含めてブラウザ内で仮生成し、サンプルを使用したことを明示します。共有アトリエの仮生成は、Cloudflareで実際の投稿写真から行い、Xserverからは既存の写真を読み出すだけです。

[ASSUMPTION / ユーザーのデモ特例指示] 正式な `Work` と別の一時的な `Draft` として実装し、文言を `demo.draft.*` に追加します。本番のM1〜M4へは追加しません。

## GLOBALのピクセル表示

ユーザーの表示拡大の依頼に合わせて、デモの常設拡大鏡を108×108から162×162へ、中心の1ピクセルを12×12から18×18へ変更しました。「あなたのシール」からのズームも18倍です。近傍は同じ9×9で、座標・中心の黒枠・元の画像は保持します。狭いスマホでは座標説明を拡大鏡の下へ配置します。これは `docs/requirements.md` S-07の12倍・108pxから、今回の指示で変更したデモ専用の表示です。

## カメラが使えないとき

撮影画面の「許可の手順を見る」から、iPhone・iPad / Safari、Android / Chrome、PC / Chrome・Edge、その他のブラウザの手順を選べます。サイトの許可と端末側の許可を見直してから、同じ画面の「カメラを再確認する」で撮影を再開します。プレビューやアプリ内ブラウザで利用できない場合は、画面に表示したURLを通常のブラウザで開きます。権限拒否・カメラ未検出・起動失敗・非対応・安全な接続でない場合を区別します。撮影を離れた後に許可しても、そのリクエストのカメラは停止します。

[ASSUMPTION / デモ用文言] ユーザーが依頼したカメラ復旧導線として、Webブラウザの許可手順と失敗原因の案内を `demo.camera.*` に追加します。正式な権限説明と拒否見出しは `docs/copy.md` をそのまま使用します。WebページからOSやサイトの許可を変更するボタンにはせず、端末側での変更手順と再試行を提供します。

手順の参照元: [Chrome（Android）](https://support.google.com/chrome/answer/2693767?hl=ja&co=GENIE.Platform%3DAndroid)、[Safari（iPad）](https://support.apple.com/ja-jp/guide/ipad/ipad8ea0fc1a/ipados)、[Firefox](https://support.mozilla.org/en-US/kb/how-manage-your-camera-and-microphone-permissions)、[Windows](https://support.microsoft.com/en-us/windows/privacy/manage-app-permissions-for-a-camera-in-windows)。自動テストは擬似カメラと権限エラーを使用します。実機のOS設定の変更やカメラの物理的な故障は自動操作で検証できません。

## 既存の端末内デモ

初期の「あさ」と、以前に端末内で作成したアトリエは、そのまま残ります。一覧では「ひとりで試す」と表示します。ここには従来のダミー履歴と、ヘッダー右側の日付の3回タップで開く進行役パネルがあります。

このアトリエで「コードを共有する」を押すと、同じ名前・定員の共有アトリエを新しく作成します。共有アトリエには、新しい招待コードが発行されます。古い端末内デモの写真やダミー履歴は共有しません。

## XserverとCloudflareへの反映

Cloudflare APIトークンは対象アカウントのWorkers編集権限に限定することを推奨します。Global API Keyを使う場合は登録メールアドレスも必要です。Windowsでは `LocalApiKeys/cloudflare` と `LocalApiKeys/xserver` に保存し、実行する子プロセスにだけ渡します。キーをチャット・Git・公開環境変数へ保存しません。

1. Xserverで `schiild.pickleballnavi.jp` と独自SSLを用意し、SSH公開鍵を登録します。SSHのホスト鍵を確認・記録してください。証明書検証やホスト鍵検証は無効化しません。
2. `apps/demo/scripts/configure-xserver.ps1` をPC上で実行します。画像ディレクトリは `/home/<server-id>/schiild-demo-images` のように、すべての `public_html` の外にします。設定と共有署名キーはアクセスを制限した `.deploy-private/` に保存されます。既存の署名キーを作り直さないでください。
3. 対象アカウントを `CLOUDFLARE_ACCOUNT_ID` に設定し、次を実行します。有料プランへの切り替えは不要です。利用量の上限に達すると制限されます。

```sh
pnpm install --frozen-lockfile
pnpm --filter demo exec wrangler deploy
```

4. `.deploy-private/storage-secret.txt` の値を、チャット外の伏せ字入力または標準入力でWorkerの `XSERVER_STORAGE_SECRET` に登録します。コマンドの引数に秘密の値を含めません。

```sh
pnpm --filter demo exec wrangler secret put XSERVER_STORAGE_SECRET
```

5. デプロイ結果のWorker URLに `/api/atelier` を付け、公開用環境変数を設定してUIを書き出します。以下はPowerShellの例です。この変数はAPIのURLのみで、秘密情報を含みません。

```powershell
$env:EXPO_PUBLIC_DEMO_API_URL = 'https://schiild-demo-api.black-field-ae8f.workers.dev/api/atelier'
node apps/demo/scripts/prepare-xserver.mjs
& apps/demo/scripts/deploy-xserver.ps1 -CheckOnly
& apps/demo/scripts/deploy-xserver.ps1
```

アップロード先は設定したサブドメインのdocument rootだけです。画像用PHPはHMAC署名したGET/PUTだけを受け付け、同じキーの画像を上書きしません。認証・アトリエ・抽選・生成の処理やDBをXserverに置きません。署名キーと非公開画像を静的UIに含めません。

配置後は、HTTPS、署名なしの画像アクセス拒否、異なるブラウザでの招待・写真投稿・同じ作品の開封・再読み込みを確認してください。Worker側のCORSは `wrangler.jsonc` の `ALLOWED_ORIGINS` に記載したUIだけを許可します。

## 以前のNetlify版

`https://schiildmoc.netlify.app/` は、移行確認中も既存のFunctions・Blobsで動作します。下記は旧サイトを維持する場合の手順です。Cloudflare版の画像はXserverに保存し、Netlify Blobsへは保存しません。

Netlifyの既存データは自動移行しません。旧サイトの共有アトリエ・写真・作品・ブラウザの識別情報を残しています。新しいドメインではブラウザの保存領域が別になるため、同じブラウザでも別の参加者として開始します。旧サイトの招待コードは新しいAPIでは使えません。データ移行と本人の引き継ぎは、別途確認して実施する必要があります。

共有機能を使うには、静的ファイルとFunctionsを一緒に配置します。`dist/`を手動でアップロードするだけでは、共有APIが配置されません。

既存サイト `https://schiildmoc.netlify.app/` の管理者が、修正を取り込んだ`demo`ブランチをGit連携の対象にしてください。リポジトリルートの`netlify.toml`で、次の設定を指定しています。

- ビルド: `pnpm --filter demo build:web`
- 公開ディレクトリ: `apps/demo/dist`
- Functions: `apps/demo/netlify/functions`
- Node.js: 24

CLIから反映する場合は、まず既存サイトを選択し、その後にプレビューを作成します。

```sh
pnpm install --frozen-lockfile
pnpm --filter demo build:web
netlify login

netlify deploy --config netlify.toml --dir apps/demo/dist
# プレビューで招待・写真送信・生成を確認してから公開する
```

`netlify link`では、必ず既存の`schiildmoc`を選びます。Blobsはそのサイトに紐づく永続ストアを使うため、別のNetlifyサイトにはデータが引き継がれません。

別のターミナルで`pnpm --filter demo test:browser`を実行すると、独立したブラウザ状態でカメラ撮影・招待・投稿同期・共同生成・再読込を検証します。模擬カメラを使うため、iPhoneやAndroidの実機検証とは区別します。

`DEMO_SECOND_ORIGIN=1`では8086も同じ確認用ストアへ接続します。`DEMO_FIXTURE=1`では検証用の単色画像2枚から作品を作り、招待URLを標準出力に表示します。どちらもローカル確認用サーバーのオプションです。

## 保存とアクセス

ブラウザ内で生成した秘密の識別情報で、そのブラウザの参加を確認します。その値は招待リンクに含めません。共有APIは参加者だけに作品を返し、生成操作は作成者だけに許可します。Cloudflare版はDurable ObjectのSQLiteトランザクションと条件付き更新で、同時参加・同時投稿による上書きを防ぎます。SQLiteに画像バイナリを格納しません。

カメラ写真は1080×1080のJPEGとして検証し、メタデータを除いて保存します。元の写真を参加者へ配信するAPIはなく、生成したシールトを共有します。送信に失敗した場合は、確認画面に写真を保持して再試行できます。

ブラウザデータを消すと参加者としての識別情報も失われます。未登録の参加者は、識別情報を消すと復元できません。登録後はIDとパスワードで参加アトリエ・預かり作品を別端末でも復元できます。ログイン前からの参加情報は登録時に引き継ぎます。既存アカウントへログインする場合、未登録の参加情報は自動で統合しません。招待コードの失効と共有データの削除は、このデモでは提供しません。

## 今回の範囲

[ASSUMPTION / ユーザー指示に基づく変更] 友達との共同制作をその場で体験するため、共有アトリエは当日参加と作成者による即時生成を採用します。元の要件の翌日参加・日次バッチは、本番側の仕様として残します。

共有版でも、作品の生成にはデモ用TypeScriptエンジンと暫定32色パレットを使います。本番Rust/WASMへの接続、プッシュ通知、公平性を外部から検証できる抽選は今回の対象に含めません。共有アトリエにはダミーの参加者・写真・作品を追加しません。

Cloudflare画像コーデック・Xserver署名ゲートウェイ・SQLite・CORSを自動テストします。実際のPHPとworkerdを使う追加テストは `DEMO_PHP` と `DEMO_WORKER_BUNDLE` を設定して `pnpm --filter demo test` を実行します。未設定の場合、この2件はスキップとして報告されます。実機カメラの許可ダイアログ、実端末の撮影品質、一斉配信・通知は自動テストで再現しません。

## アカウント・GLOBAL・設定

左上のSchiildアイコンからアカウントページへ進みます。IDは英小文字・数字・_・-で3〜24文字（先頭は英数字）、パスワードは12〜128文字です。ログインすると参加アトリエと作成者の生成権限を復元します。表示名を変更でき、預かり作品から開封ページへ移動できます。

パスワードは16バイトの個別ソルトとPBKDF2-HMAC-SHA256（100,000回）のハッシュだけをCloudflareに保存します。セッションは暗号学的乱数32バイト、有効期限7日、DBにはトークンのSHA-256ハッシュを保存します。ログアウト時にはサーバー側で無効化します。IDごとの試行上限は10分間5回で、同時試行も条件付き更新で数えます。公開APIでは認証操作をIPごとに1分10回までに制限します。メール確認、パスワード再発行は提供しません。アカウント削除の手順は下記に記載します。

共有GLOBALはUTC日付ごとに、実際の写真を記録した参加者の平均色を暫定32色へ減色し、1人1ピクセルとして256×256画像に配置します。同じ参加者の複数アトリエへの投稿は重複しません。全利用者に共通の画像を返し、自分が投稿した日のみ自分の位置を表示します。当日の投稿に合わせて更新され、翌日から固定します。既存の共有作品の日付は保存済み写真から復元します。過去30日の端末内履歴と端末内で生成した作品は「サンプル作品」と表示し、共有GLOBALの集計に混ぜません。

共通の下部ナビゲーションはアトリエ選択・コード共有・アカウント・設定でも表示します。「アーカイブ」から日付ごとのGLOBALを選べます。設定の「開封・ズームの演出を省略する」はこのブラウザに保存されます。通知は未対応と表示します。Xserverは静的UIと署名付き画像保存のみ、認証と共有処理はCloudflare内です。

旧Netlifyサイトには今回のログイン機能を反映しません。新しいUIを利用する配置先はCloudflare APIを設定したXserver版です。

## アカウントの完全削除（デモ専用）

ID・パスワードでログインし、左上のアイコン →「設定」→「アカウントを削除する」と進みます。削除対象のアカウントIDと現在のパスワードを入力し、削除内容の確認後に「アカウントを完全に削除する」で確定します。誤ったパスワードでは削除できず、確認画面の「やめる」は何も変更しません。

[ASSUMPTION / ユーザー確認済みのデモ特例] アカウントID、表示名、パスワードハッシュ、連携情報を削除し、全セッションを失効させます。参加中のアトリエから退出し、作成者の生成権限は残っている最初の参加者へ引き継ぎます。投稿済みの写真・区画・共同作品・GLOBALは匿名の記録として残し、画像そのものは変更しません。これは写真も削除する本番の文言・仕様とは異なるため、デモ専用キーで削除範囲を明示します。本番M1〜M4のコードや正式な文言は変更していません。

元のアカウント、過去の参加情報、預かり作品との紐付け、専有面積の履歴は復元できません。同じIDを新たに登録しても新しい参加者となり、以前の記録は戻りません。サーバーでは参加者とセッションのハッシュに削除・失効フラグだけを残し、削除前の認証情報や途中のリクエストからの再有効化を防ぎます。画像の保存キーは非公開のハッシュを含んだまま保持しますが、アカウント情報との対応は消去します。

削除確定時にこのブラウザのSchiild用保存領域（参加情報・サンプル作品・演出設定も含む）を消去します。別端末のログインも直ちに無効になり、その端末が次にAPIへ接続したときにローカル情報を消去します。共有アトリエを開いている端末は定期更新で失効を検出します。Google認証の公開設定は保留したままで、現在の削除画面はID・パスワードのアカウントに対応します。

`account-removal.test.mjs` は匿名化後の画像・区画保持、全セッションと元の端末識別情報の失効、同じIDの新規登録による履歴復元の防止、試行制限、削除中のログインとの競合、SQLiteトランザクション失敗時の全変更の巻き戻しを検証します。`account-removal-browser.mjs` は確認・取消・パスワード不一致と、別端末の失効・ブラウザ保存領域の消去まで確認します。workerd/PHPテストでも実際のCloudflare実行環境と画像保存を通して削除を検証します。

## Googleアカウントでの認証（デモ専用）

2026年10月9日：ユーザーの指示によりGoogle側の設定・有効化を保留しています。ID・パスワード認証を継続して使用できます。

[ASSUMPTION / ユーザーのGmail認証依頼に基づく変更] Google Identity Servicesの公式ボタンからGoogleアカウントを選んでログインします。新規登録はそのブラウザの共有参加情報を引き継ぎます。既存IDのアカウントに連携する場合は、先にID・パスワードでログインし、アカウントページのGoogleボタンを押します。メールアドレスの一致による自動統合は行いません。連携済みなら別端末でもGoogleで同じアカウントへ戻れます。端末内のサンプル履歴は移行しません。

Google側での設定が完了するまで、Googleボタンは表示しません。設定手順は次のとおりです。

1. Google CloudのGoogle Auth Platformでプロジェクトを作成または選択し、ブランディング、サポートメール、対象「外部」を設定します。
2. WebアプリケーションのOAuthクライアントを作成します。承認済みJavaScript生成元は `https://schiild.pickleballnavi.jp` です。ポップアップのJavaScriptコールバックを使うため、リダイレクトURIは不要です。
3. 基本の `openid / email / profile` のみを使います。Gmail APIやメール本文を読む権限は要求しません。テスト中はGoogle側でテストユーザーを指定します。一般利用者へ公開する場合はGoogle側の公開状態と表示される確認事項を確認してください。
4. ホームページは `https://schiild.pickleballnavi.jp/`、プライバシー情報は `https://schiild.pickleballnavi.jp/privacy.html` です。運用内容に合うことを確認し、承認済みドメイン `pickleballnavi.jp` と一緒にGoogleへ登録します。
5. `node apps/demo/scripts/configure-google.mjs` を実行し、`http://127.0.0.1:8799/` にWeb用クライアントIDを入力します。Git対象外の `apps/demo/.deploy-private/google-auth.json` へ保存します。クライアントシークレットやGoogleパスワードは不要です。
6. 同じクライアントIDをCloudflare Workerの `GOOGLE_CLIENT_ID` に設定し、WorkerとUIを配置します。CLIでは `pnpm --filter demo exec wrangler secret put GOOGLE_CLIENT_ID` の対話入力を使えます。このIDは公開識別子ですが、認証を有効化する対象をローカル設定に限定します。UIはAPIからIDを取得するので、Google設定だけの変更でUIを再ビルドする必要はありません。

ローカル動作をGoogleでも確認する場合は、Googleの承認済み生成元に `http://localhost` と `http://localhost:8085` を追加し、確認用サーバーの `GOOGLE_CLIENT_ID` 環境変数へ同じIDを渡します。鍵やGoogle認証トークンをチャット、コミット、静的ファイルへ貼り付けないでください。

Cloudflareでは `jose` とGoogleの公開鍵を使い、RS256署名、発行者、クライアントID、発行・失効時刻、確認済みメール、nonceを検証します。Googleの `sub` をSHA-256で識別し、Google IDトークンは保存しません。5分間有効のnonceはブラウザの認証情報に結び付け、条件付き更新で一度だけ受け付けます。Googleアカウントと参加者の連携はSQLiteトランザクションで確定します。ログイン後は既存の7日間セッション、ログアウト失効、IPごとの認証操作制限を適用します。ID・パスワードの認証も継続して利用できます。

`google-auth.test.mjs` は署名偽造、別アプリのトークン、失効、nonceの取り違え・再利用、同時登録、既存IDとの連携、メール一致による誤統合の防止を検証します。`google-browser.mjs` はGoogleサービスだけを模擬し、署名済みトークンを実際のアカウント処理へ渡してボタン、再試行、ログアウト、別端末の復元を確認します。追加のworkerd/PHPテストではGoogle公開鍵の応答だけを模擬し、Cloudflare実行環境の署名検証とSQLite連携まで確認します。実際のGoogleアカウントの選択・同意は、Google側設定後に本人がブラウザで確認する必要があります。

## アトリエごとの投稿と専有面積（デモ専用）

[ユーザー依頼・集計方法承認済み] 参加するアトリエごとにUTC日付につき1枚を撮影・確定できます。同じアトリエの確定済み写真は取り消し・差し替えできません。新規参加・作成・アトリエ切り替えによる写真の自動投稿は行いません。この仕様変更はデモだけに適用し、本番M1〜M4、要件定義書・正式文言は変更しません。説明・確認画面の文言はデモ専用キー／上書きで区別します。

今日の画面または左上アイコンのプロフィールから「今日の自分の投稿」へ進み、自分が今日記録した写真と、同じ写真を追加するアトリエを選択できます。元の写真のプレビューは本人だけに返します。投稿済み・生成中・受付終了・対象日が異なるアトリエは選べません。複数の追加先はそれぞれ確定し、成功・失敗をアトリエごとに表示します。退出後も自分の当日投稿を再利用できます。翌日には前日の写真を再利用できません。共有写真は内容別の保存キーにし、再利用時には画像を複製せず既存の写真を参照します。従来の保存キーも引き続き読めます。

「あなたの専有面積」は投稿した本人の区画の画素数（px）と画像全体に占める割合です。アトリエは128×128画像上のBSP矩形の幅×高さ、GLOBALは256×256画像上の1 pxです。今日の画面・仮表示・開封後の作品・GLOBALで表示します。未投稿では0 pxです。複数アトリエに投稿しても同じ人のGLOBALは1日に1 pxのまま、その日に最初に共有した写真の色を保ちます。

プロフィールの「これまでの総専有面積」は「GLOBALの累計」と「アトリエの累計」を分けます。確定済みの投稿区画を日付ごとに合計し、未生成の区画と退出したアトリエも含めます。参加者の対応は日付ごとの記録を使い、翌日に同じ区画へ参加した別の人へ過去の面積を引き継ぎません。登録・別端末でのIDログイン後にも同じ集計を復元します。30日分のダミー履歴は含めません。「ひとりで試す」の実際の撮影分はブラウザ内の別集計で表示し、共有GLOBALやアカウントの集計に混ぜません。

`personal-area.test.mjs` は異なる写真・明示的な再利用・部分失敗・本人限定の元写真・同時投稿・UTC境界・旧保存形式・退出／区画再利用・ログイン後の復元を検証します。`personal-area-browser.mjs` ではスマホ幅で別々の撮影、追加先選択、確定、仮表示、GLOBAL、プロフィールと再ログインを通して確認します。workerdとPHPの統合テストは、新形式の写真キーと既存写真の再利用も実際の実行環境で検証します。

## GLOBALの手動ズーム（デモ専用）

GLOBALの画像を2本指のピンチで1〜64倍へ拡大・縮小し、1本指のスワイプで移動できます。拡大率のスライダーは指で動かせます。PCではマウスドラッグ、ホイール、拡大・縮小ボタンでも操作できます。ダブルタップ／ダブルクリックはその位置へ拡大します。「全体に戻す」で倍率・位置・選択を戻します。画像だけがジェスチャーを受け、画面外の通常スクロールを妨げません。キーボードの±・矢印・Home・Enterでも操作できます。

画像をタップ／クリックすると、選んだピクセルを拡大した色見本と座標を表示し、投稿のあるピクセルと未描画セルを区別します。GLOBALは1人1日1ピクセルなので、確認対象はその日のシールの色です。他の人の元写真や本人識別情報を返しません。既存の「あなたのシール」へのズームも残します。参加していない日やアーカイブの過去作品でも手動操作できます。30日分のダミーはサンプル表示を保ちます。

`global-view.test.mjs` で拡大の支点、画素座標の逆変換、倍率・移動の限界を確認し、`global-explorer-browser.mjs` で実際のタッチイベントによるピンチ・スワイプ・タップ、PC操作、リサイズ、アーカイブを検証します。
