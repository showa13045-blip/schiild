# Schiild デモ

説明用プレゼンと、少人数の体験テストのための独立したExpo Webアプリ。ブランチは `demo`。`main` へマージしない。本番M1〜M4のコード・API・DB・認証は使用しない。

## 起動・静的書き出し

リポジトリルートでNode.js 24と指定のpnpmを使用する。

```sh
pnpm install --frozen-lockfile
pnpm --filter demo start
pnpm lint
pnpm --filter demo typecheck
pnpm --filter demo test
pnpm --filter demo build:web
```

配置するファイルは `apps/demo/dist/` のみ。Expoの `web.output: single` による静的SPAで、Nodeサーバーは不要。スマホのカメラにはHTTPSが必要。PCのlocalhostも利用可能だが、スマホからHTTPのLANアドレスで開く方法ではカメラが動かないことがある。

静的ファイルのローカル確認：`cd apps/demo` → `node scripts/serve.mjs` → `http://localhost:8085/`。これは確認用配信だけで、アプリ用APIではない。

## 体験の進行

1. 「あさ」に参加済みの状態で開始。初期区画は匿名、履歴は30作品。
2. 「1日に1枚だけ」からカメラへ。「次へ」でブラウザのカメラ許可を求め、四角いシャッターで撮影する。写真選択・フィルタ・アルバム導線はない。
3. 撮影した写真と「今日のシールは一度きりです」を確認し「確定する」。1080×1080のJPEGをこの端末内に保存する。
4. 約2.2秒ごとに他の区画が埋まる。合計10 of 12まで進み、2区画をVoidCellとして残す。実在の他ユーザーではない。
5. 進行役が左上の「Schiild」を1.1秒以内に3回タップ。隠しパネルの「次へ → 00:15 UTC」で当日の受付と待ち時間を進める。
6. 未開封は空面。「ひらく」で、120ms後から230msごとに12タイルを離散表示。最終タイルから500ms後に記録を500msフェード、記録の表示開始からさらに1000ms後に預かり手を600msフェードする。空区画も同じ順序・間隔で置く。
7. 完成後「GLOBAL SCHIILD」へ。自分のピクセルを示す文を押すと連続ズームし、移動終了後に短い間を置いて枠が出る。全体像と9×9近傍の拡大鏡も常設。
8. 下部「アーカイブ」で履歴へ。今回の作品は開封後に加わる。

初回開封中は作品をタップすると即完了。2回目の閲覧は完成状態。`prefers-reduced-motion` では演出を省略する。

### 進行役の隠しパネル

- 「あなたが預かります」／「ゆきさんが預かります」で抽選結果を切替。生成前に選ぶか、選択後にパネル内「ひらく」を押して同じ作品を再演する。
- 生成前の「次へ」は当日の生成・開封へ進む。生成済みの「次へ」は次の論理日へ進め、新しい1枚を撮れる状態にする。
- パネルの「ひらく」は開封済みフラグを解除する進行役専用の再演操作。
- 「もう一度試す」はこのデモの端末内状態だけをリセットし、30日分のダミー履歴から再開する。

参加者にパネルの場所を説明する必要はない。ここは秘密の認証機能ではなく、操作上の隠しパネル。公開URLを知る人が3回タップすれば開ける。

## Netlifyへ配置

継続利用にはNetlifyのユーザーアカウントが必要。アプリ自体にはログインを設けない。今回の配置先は https://schiildmoc.netlify.app/ 。

匿名デプロイを利用した場合は1時間以内にアカウントへ引き取る。その後、プロジェクトがPrivateなら概要画面の **Make public** を選ぶ。引き取りだけでは公開設定は変わらない。シークレットウィンドウでログインなしのアクセスを確認してからURLを配る。

最短手順：書き出し後、Netlifyの手動デプロイ画面で **`apps/demo/dist/`** をアップロードする。発行されたHTTPS URLをスマホで開く。リポジトリ全体や撮影データをアップロードしない。

CLIを使う場合：

```sh
netlify login
netlify deploy --dir apps/demo/dist
# プレビューを確認して、同じデモサイトへ公開
netlify deploy --dir apps/demo/dist --prod
```

Git連携の場合は `demo` ブランチのみを選び、リポジトリルートから `pnpm --filter demo build:web`、公開ディレクトリ `apps/demo/dist` を指定する。`main` や本番プロジェクトに接続しない。設定例は `netlify.toml`。自動検出されなければダッシュボードで同じ値を指定する。

## Vercelへ配置する場合

Git連携で `demo` ブランチを選択し、Root Directoryを `apps/demo`、FrameworkをOther、Build Commandを `pnpm build:web`、Output Directoryを `dist` とする。ワークスペースのロックファイルを読めるようリポジトリルートのファイルをビルド対象に含める。設定例は `vercel.json`。独立したデモプロジェクトへ配置し、既存本番サイトを上書きしない。

[Expo公式の静的配信手順](https://docs.expo.dev/guides/publishing-websites/)

## 本番との境界・再現できないもの

| 項目 | デモでの扱い |
|---|---|
| 実機カメラと権限 | 実際のブラウザカメラを使用する。ただし許可ダイアログ・設定導線・端末間の差は制御できない。HTTPSと本人の許可が必要。拒否画面と再試行は実装済み。自動試験は模擬カメラであり、iPad/Android実機の検証とは区別する |
| プッシュ通知 | 実装しない。画面内で開封へ進める |
| 一斉配信 | サーバーや共通時計がなく、端末内の時間操作で代替。表示カウントダウンはデモ用の固定15分 |
| 複数端末での同時参加 | 同期しない。他の投稿はダミーの自動補完 |
| 抽選 | 指定した結果を表示。本番の公平性・公開検証・CSPRNGを再現しない |
| 生成 | `src/engine.ts` のデモ専用TypeScript。BSP整数格子、センタークロップ、面積平均、Oklab最近傍、Floyd–Steinberg減色を実装。暫定32色・ダミー参加者を使用。Rust/WASMと一致せず、本番へ流用しない |
| 全生命作品 | 周囲のピクセル・統計はダミー。自分の1ピクセルだけ撮影写真の平均色から生成。世界の投稿集計ではない |
| 過去作品 | 最初の30日分は端末内のダミー生成。実際の利用履歴ではない |
| 画像審査・通報・復元 | 実装しない。アップロード、クラウド保存、端末間バックアップもない |

状態のキーは `schiild.demo.ateliers.v2`。旧 `schiild.demo.v1` のデータは初回に「あさ」へ引き継ぐ。localStorageのみを使い、撮影データを別端末へ渡さない。ブラウザデータの消去・プライベートモード終了・容量制限で消失しうる。端末を共用するテストでは進行役がリセットする。

## 文言と確認

`src/copy.json` は `docs/copy.md` のキーと値をビルド時に抽出。本文を独自に書き換えない。パネルも既存キーを利用。アトリエ名・人物名・数字はデモデータとして補間する。禁止語・感嘆符のルールはルートの `pnpm lint` をそのまま適用する。

フォントはInter / Noto Sans JPの400・500だけを文字サブセット化して同梱し、外部CDNへ接続しない。ライセンスは `public/fonts/` に同梱。

ブラウザ試験：別ターミナルで静的サーバーを起動し、`pnpm --filter demo test:browser`。初回は `pnpm --filter demo exec playwright install chromium`。Windowsでは既存ブラウザの実行ファイルを `DEMO_BROWSER` 環境変数で指定可能。模擬カメラ、拒否、端末内保存、開封時刻、スキップ、再演、アーカイブ、ズーム、外部リクエストがないことを検査する。

ユーザーが今回明示したデモ専用TypeScript・ダミー履歴・抽選操作・時間操作は、ルートAGENTS.mdの本番規約に対する今回限定の例外。本番側のファイルは変更しない。

## アトリエの作成・参加・招待・削除

アトリエ画面の「アトリエ ＋」から一覧を開く。名前を選ぶと、そのアトリエの今日・開封・アーカイブに切り替わる。既存の「あさ」の30作品は維持し、新規作成は履歴ゼロから始まる。定員2 / 5 / 12 / 20の構図プレビューを確認して作成する。

「コードを共有する」は、名前・定員・コードを含む招待リンクを端末の共有画面へ渡す。共有機能がないブラウザではリンクをクリップボードへコピーする。表示されたリンクも手動コピーできる。「コードをコピーする」は8文字のコードのみをコピーする。サーバー照会がないため、別端末の初回参加には必ずリンクを渡す。8文字コードだけで検索できるのは、そのブラウザが既に知るアトリエに限る。「コードで参加する」にはリンク全体も貼り付けられる。共有の送信先と送信は操作する本人が選ぶ。

招待先ではプレビューと翌日開始の説明を表示し、「参加する」を押して参加を確定する。招待先には新しいローカル状態を作り、写真・履歴・作成者の識別子は共有しない。参加日の投稿は無効で、隠しパネルで生成後にもう一度時間を進めると翌日になる。投稿できるアトリエの間では、同じ論理日の既存写真を使い、撮り直しを許さない。

作成したブラウザだけに「アトリエを削除する」を表示し、確認後に対象のローカル状態と履歴を消す。初期の「あさ」と招待参加したアトリエには表示しない。削除関数でも作成者の端末識別子を検査する。ただし認証ではなく、端末内データの改変に耐える権限管理ではない。他端末の状態や既に渡した招待リンクは失効・削除されない。

[ASSUMPTION / 承認済み] この削除範囲と端末内の作成者判定、非同期の招待体験、および削除の2文言はユーザー確認済み。追加文言は `src/demo-copy.ts` のデモ専用キーで管理し、正式な `docs/copy.md` と本番コードは変更しない。招待先の人数・通算枚数はローカルの試作用データであり、共有先の実際の状況を示さない。

追加ブラウザ試験は2つの独立したブラウザ状態を使い、作成・定員・保存・招待・翌日参加・不正/重複コード・削除権限・取り消しを確認する。`pnpm --filter demo test:browser` に含まれる。
